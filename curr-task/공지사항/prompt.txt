첨부된 4개 화면(공지 목록 / 공지 상세 / 신규 작성 / 수정)과 동일한 UI·레이아웃으로 공지사항 게시판을 구현해줘.

[0. 필수 선행]
- 작업 전에 프로젝트 내 `localstorage_to_firebase_guidelines.md`를 먼저 읽고, 그 지침을 모든 데이터 처리 코드의 최우선 규칙으로 따른다.
- 이 지침과 아래 내용이 충돌하면 지침 파일을 우선하고, 충돌 내용을 작업 후 알려준다.
- 기존 AGENTS.md가 있으면 그 규칙도 함께 따른다.

[1. 개발 방식]
- 백엔드/DB 없이 브라우저 localStorage만 사용한다.
- 추후 Firebase(Firestore)로 마이그레이션할 예정이므로, UI 코드가 localStorage를 직접 호출하지 않도록 데이터 접근 계층(Repository/Service)을 분리한다.
- 이 계층의 함수는 모두 async(Promise 반환)로 작성해서, 나중에 구현체만 Firebase로 교체하면 되게 한다.
- 필요 함수 예: getNotices(조건), getNoticeById(id), createNotice(data), updateNotice(id, data), deleteNotice(id)

[2. 화면 및 기능]
1) 목록 (이미지 4)
   - 상단: 카테고리 셀렉트(すべて 기본) + 키워드 검색창 + 「新規投稿」 버튼
   - 테이블: No. / 타이틀(상태 뱃지 포함) / 카테고리 / 투고일 / 우측 화살표, 행 클릭 시 상세로 이동
   - 페이지네이션: 한 페이지 7건, 이전/다음 + 페이지 번호
   - 최신글이 위, No.는 내림차순
   - 검색은 제목 기준 부분일치, 카테고리 필터와 조합 가능
2) 상세 (이미지 3)
   - 뱃지·제목·날짜, 링크 복사 버튼(+SNS 아이콘), 본문, 썸네일 이미지 영역
   - 하단: 「一覧に戻る」, 「編集する」
3) 신규 작성 (이미지 1)
   - 타이틀(필수, 100자 제한 + 글자수 카운터), 카테고리(필수 셀렉트), 본문(필수, 툴바 포함 에디터, 비어 있을 때 쿠로미 안내 일러스트), 첨부파일(최대 5MB / 10개)
   - 필수값 미입력 시 검증 메시지를 표시하고, 「投稿する」 클릭 시 저장 후 목록으로 이동
   - 「キャンセル」 클릭 시 목록으로 이동
4) 수정 (이미지 2)
   - 기존 데이터를 폼에 채워서 표시, 상단에 현재 제목과 날짜 표시
   - 「更新する」 클릭 시 저장 후 상세로 이동

[3. 데이터 모델 (Firestore 문서 구조를 고려)]
notices 컬렉션 1건 = {
  id: string (문서 ID, UUID 등),
  no: number (표시용 번호),
  title: string,
  category: string,
  badge: string (お知らせ / イベント / キャンペーン),
  content: string (HTML),
  attachments: [{ name, size, type, dataUrl 또는 url }],
  createdAt: ISO 문자열 또는 timestamp 변환 가능한 값,
  updatedAt: 동일
}
- localStorage 키는 `notices` 하나로 두고, 최초 실행 시 이미지 4의 샘플 7건(1001~1007)으로 시드 데이터를 넣는다.
- 상세 이미지(1002)의 본문 내용은 샘플 데이터에 그대로 사용한다.
- localStorage 5MB 한도를 고려해, 첨부파일은 저장 방식을 지침 파일 규칙에 따라 처리한다.

[4. 디자인]
- 파스텔 핑크 테마, 리본·하트 장식, 캐릭터 일러스트 배치, 둥근 카드형 박스, 핑크 그라데이션 버튼은 이미지와 동일하게 재현한다.
- 헤더/푸터는 이미지 구성 그대로 만든다.
- 캐릭터 이미지는 파일이 없으면 자리 표시용 에셋으로 대체하고, 교체 위치를 알 수 있게 주석을 남긴다.
- 모든 UI 텍스트는 이미지와 같은 일본어를 사용한다.
- 반응형(모바일)도 대응한다.

[5. 산출물 및 완료 조건]
- 파일 구조와 구현 요약을 먼저 제시한 뒤 코드를 작성한다.
- 위 4개 화면의 이동 흐름(목록→상세→수정→상세, 목록→작성→목록)이 끝까지 동작해야 한다.
- 새로고침해도 데이터가 유지되어야 한다.
- 마지막에 "Firebase 마이그레이션 시 교체해야 할 파일/함수 목록"을 정리해서 알려준다.
